# 阅读指南：沿着一笔订单学习平台工程 {.unnumbered #reading-guide}

用户点击“下单”时，只关心货有没有、钱有没有扣、订单是否成功。平台工程师还必须回答：请求被送到哪个副本，数据库何时承诺持久化，事件是否送达，发布能否撤回，监控失明时谁来通知。这本书用同一套 storefront 系统连接这些问题。

**建议先读第 2 章。**熟悉业务之后，读第 1、3–6 章理解平台如何承载它，再读第 7–10 章理解故障、恢复、发布和调查。第 11、12 章讨论控制面与管理工具自身；第 13 章把这些能力合成一次工程判断。有经验的读者可以先做章末题，再回到解释中检查自己的推理。

每个重要知识单元从一个具体问题出发。图负责显示关系、时间和状态；源码负责说明真正执行的判断；截图负责指导你在软件中找线索；实验数字负责检验解释的范围。正文中的 E 编号链接到附录的原始记录。代码节选带源文件行号，点击来源可继续阅读完整实现。所有代码锚定于基线提交 `510ec87`，不是为了教学而重新实现的伪代码。

## 怎样区分图与事实 {.unnumbered .unlisted}

| 标签 | 读法 |
|---|---|
| 机制示意图 | 作者根据实现绘制的模型；箭头表示调用、状态或因果，不能当作运行截图 |
| 历史实测 | 仓库保留的运行数据；本轮出版没有重新运行实验 |
| 模型推算 | 公式与假设推出的数值，适合形成预测，需要测量检验 |
| 真实界面局部 | 原始 Grafana / Tempo 捕获的裁剪；编号是编辑解读，不是软件自身的标记 |
| 终端记录节选 | 历史命令结果的排版或局部，不是 GitLab、Argo CD 网页 |

全书保留 `[真实]`、`[模拟]`、`[注入]`、`[虚拟]` 的区别。三个可用区是单机节点标签；payments 是模拟的第三方；故障注入使用真实进程；KWOK 的节点与 Pod 是对象。它们能够帮助理解机制，不能证明真实多可用区的生产容量。

## 版本、运行与本书的边界 {.unnumbered .unlisted}

实验使用的主要版本包括 Kubernetes v1.37.0、Istio 1.31.4、KEDA 2.21.0、CloudNativePG 1.30.1、OpenTofu 1.13.9。完整版本表在仓库。它们是历史记录的环境，不是“目前最新版本”的推荐。

本版没有启动 `devops-lab` 或重跑 E0–E12。你看到的界面与数字来自历史素材，源码分析来自固定基线。没有真实界面的主题以机制图解释；没有验证的恢复、跨区域部署、第三方独立考核仍明确留空。书中保留了失败预测、误报、未找到根因的停顿，以及解封密钥丢失等事故。

学习时请区分“能复述一个结论”与“能决定下一步”。当图显示请求正在排队，你应能指出谁拥有队列；当截图显示所有应用 Healthy，你应知道它没有证明什么；当计划显示替换资源，你应能说清修复本身会打开哪个窗口。这些判断是各章练习的目标。参考答案位于附录 A，先完成推理再翻阅。

**前置知识：**能阅读 Python 异步函数、SQL 事务和基本 YAML；了解 HTTP、容器与 Git。复现环境、完整脚本与原始证据留在仓库，入口见附录 C、D。旧版 82 道实验练习及答案仍可在历史教材和源文件中阅读，新版采用与源码和案例紧密对应的综合题。
