# 阅读指南 {#preface .unnumbered}

<div class="lead">这本书用一台笔记本上的真实软件，搭建一个尽可能接近企业生产的多服务平台，然后对它做实验：测它的容量，让它扩容，把它隔离成租户，向它注入故障，删掉它再重建，给它立规矩、装告警，最后把它放大到一万个 Pod。每一章回答一个工程问题，每一个结论都有执行记录。它不是工具手册——工具的用法在各自的文档里；它想讲清楚的是机制、取舍，以及“我怎么知道这是真的”。</div>

## 每一章怎样组织 {.unnumbered}

每一章沿着同一条路走：**工程问题 → 技术原理 → 架构与实现 → 实验验证 → 结果分析 → 局限与工程启示**。章首的深色方框提出这一章要回答的工程问题，旁边列出实测得到的结论——可以先看结论，再带着“这是怎么得出来的”读下去。“原理”一节只讲后面的实验用得到的机制。每个实验先写下假设，再给出测量；章末的“局限”说明哪些事情没有测，“从实验环境到生产环境”的对照表说明这里的做法与真实生产的差别。最后是常见问题、练习（参考答案在附录 A）和小结。

实验遵循一条纪律：**假设写在实验之前，并且先提交到 Git。**所以书里有不少“假设被推翻”——它们按原样保留，因为预测为什么错，往往比预测对了更有教益。书中还记录了八起计划之外的真实事故与事件，其中最重的两起（第 11 章的 E10-1、第 12 章的 E11-1）都出自作者自己的操作，连同复盘写进了正文。

## 四种真实性标注 {.unnumbered}

| 标注 | 含义 | 例子 |
|---|---|---|
| `[真实]` | 真实运行的软件、真实的请求与数据 | Kubernetes、Argo CD、PostgreSQL、k6 产生的负载 |
| `[虚拟]` | KWOK 模拟的节点与 Pod：只有控制面是真实的，没有容器在运行 | 第 11 章的 1000 个节点、10 000 个 Pod |
| `[注入]` | 人为制造的故障或负载 | 冻结节点、切断复制、让一半请求返回 503 |
| `[模拟]` | 用实验手段代替的企业设施 | “可用区”是节点的标签，“外部支付”是自己写的模拟器，“异地”备份在同一台机器上 |

## 证据在哪里 {.unnumbered}

正文里的上标数字（例如<sup class="ev">[3]</sup>）是证据编号，每章单独编号，对应附录 D 中列出的原始记录文件——终端输出、查询结果、时间线和复盘。全部文件连同配置与脚本都在实验仓库 `github.com/miku-wwl/devops-delivery` 的 `v2/` 目录下（分支 `v2/publication`）。正文中的具体陈述另有程序逐条与这些文件比对。附录 C 按章列出每个实验的脚本和配置在仓库中的位置；仓库的 `v2/README.md` 说明怎样在自己的机器上复现。

## 边界 {.unnumbered}

全书的数字都来自一台笔记本（16 个硬件线程，虚拟机分得 15.3 GiB 内存）上的一次或几次运行，只代表这里测到的范围。本书验证的是“在受控环境中，能否正确地设计、实施、测量和排查”；它不能替代生产经验：真实生产有更大的规模、真实的用户、跨团队的协作、合规审计和长期运行才会出现的问题。书中没有虚构任何生产规模或工作经历。
