# 附录 B　术语表 {#app-glossary .unnumbered}

按拼音与字母顺序排列；括号内是首次展开讲解的章。

<div class="glossary-cols">

**allocatable（可分配资源）**　节点容量减去系统预留和驱逐阈值之后，调度器可以分给 Pod 的部分。（第 1 章）

**ambient 模式**　Istio 不向 Pod 注入 sidecar 的数据面：每个节点一个 ztunnel 负责第 4 层，按需部署的 waypoint 负责第 7 层。（第 3 章）

**APF（API Priority and Fairness）**　API server 按优先级分配并发席位、排队并在过载时返回 429 的机制。它限制同时执行的请求数，不限制内存。（第 11 章）

**app-of-apps**　一个 Argo CD 应用指向一个目录，目录里的每个文件又是一个应用；整个平台由此从 Git 引导。（第 2 章）

**burn rate（燃烧率）**　错误预算被消耗的速度；1 表示恰好在 SLO 周期结束时用完。多窗口、多燃烧率告警同时看长短两个窗口。（第 10 章）

**compaction（压缩）与 defrag（碎片整理）**　etcd 清除旧修订版本，以及把数据库文件重写、把空间还给文件系统的两个操作。（第 11 章）

**DORA 指标**　部署频率、变更前置时间、变更失败率、恢复时间。（第 9 章）

**drift（漂移）**　真实状态偏离了声明的状态。（第 12 章）

**eviction（驱逐）**　节点资源不足时，kubelet 按顺序终止 Pod 以保护节点。（第 1、5 章）

**exemplar**　直方图桶上附带的一条链路 ID，把指标上的一个点连到具体的请求。（第 10 章）

**FlowSchema / PriorityLevelConfiguration**　APF 的两种对象：前者把请求分类，后者定义一个优先级的席位、队列与借用。（第 11 章）

**GitOps**　以 Git 为唯一的声明来源，由控制器持续把运行状态拉向它。（第 2、9 章）

**HBONE**　ambient 网格节点之间的隧道：mTLS 之上的 HTTP/2 CONNECT，端口 15008。（第 3 章）

**HPA / KEDA**　按指标（HPA）或按事件源如队列积压（KEDA）自动调整副本数。（第 5 章）

**informer**　客户端的缓存模式：LIST 一次，然后靠 WATCH 保持更新。（第 11 章）

**KWOK**　不运行 kubelet 的 Kubernetes：真实的控制面管理虚拟的节点与 Pod。（第 11 章）

**MVCC**　多版本并发控制；etcd 为每次写入保留一个修订版本。（第 11 章）

**outbox（事务性发件箱）**　把要发的消息与业务数据写进同一个事务，再由中继发布，解决“双写”问题。（第 2 章）

**PITR（时间点恢复）**　基础备份加上重放 WAL，把数据库恢复到指定的时刻。（第 8 章）

**QoS 类别**　Guaranteed、Burstable、BestEffort：由 Pod 的请求与限制决定。（第 5 章）

**RPO / RTO**　故障时最多丢失多少数据（恢复点目标）与多久恢复服务（恢复时间目标）。（第 8 章）

**saga**　用一串可补偿的本地事务完成跨服务的业务流程。（第 2 章）

**selfHeal**　Argo CD 发现集群偏离 Git 时自动改回。（第 12 章）

**SLI / SLO / 错误预算**　衡量服务好坏的指标、它的目标值，以及目标允许的失败量。（第 7、10 章）

**server-side apply 与字段所有权**　由 API server 合并配置，并记录每个字段由哪个管理者设置；别的管理者改它会产生冲突。（第 12 章）

**状态（state）与状态锁**　IaC 工具记录“配置中的资源对应哪个真实对象”的文件，以及防止两次运行同时修改它的锁。（第 12 章）

**同步波次（sync wave）**　Argo CD 应用之间的先后顺序。（第 2、9 章）

**同步冒用（sync impersonation）**　Argo CD 以项目指定的服务账号而不是自己的高权限身份写入集群。（第 9 章）

**尾部采样 / 头部采样**　在整条链路结束之后，或在请求开始之时，决定是否保留链路。（第 10 章）

**WAL（预写日志）**　PostgreSQL 在修改数据之前先写的日志；复制、归档与时间点恢复都靠它。（第 8 章）

**watch 缓存**　API server 内存中的对象缓存，为 WATCH 和大多数 LIST 提供数据。（第 11 章）

**waypoint**　ambient 网格中按命名空间或服务部署的第 7 层代理（Envoy）。（第 3 章）

**熔断器 / 隔舱 / 重试预算**　调用方保护自己和下游的三种机制：对持续失败的依赖快速拒绝；限制在途调用数；限制重试占总请求的比例。（第 2、7 章）

**死人开关（dead man's switch）**　一个永远在响的心跳告警；它停了，说明告警链路自己出了问题。（第 10 章）

**协调遗漏（coordinated omission）**　封闭模型的压测在系统变慢时自动少发请求，从而漏记最慢的那些请求。（第 4 章）

**准入（admission）**　请求通过认证和授权之后、写入之前的检查与修改。（第 6 章）

**ztunnel**　ambient 网格在每个节点上的第 4 层代理，负责 mTLS 与身份。（第 3 章）

</div>
